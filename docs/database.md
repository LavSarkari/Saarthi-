# Database Architecture

## Firebase Firestore

Saarthi uses Firebase Firestore as its primary real-time persistence layer. Firestore was selected for its offline-first capabilities, real-time synchronization, and seamless integration with React and Firebase Auth.

### Collections & Schemas

#### 1. `tasks` Collection
The core operational entity. Each document represents a major user commitment (e.g., an assignment, project, or exam).
- **`userId`** (string): The Firebase Auth UID of the owner.
- **`title`** (string): The name of the commitment.
- **`description`** (string): User notes or instructions.
- **`deadline`** (timestamp): The absolute due date.
- **`riskScore`** (number): Continuously updated percentage (0-100) generated by the Completion Confidence Engine.
- **`riskZone`** (string): "secured", "caution", or "critical".
- **`subtasks`** (array): The individual execution steps generated by the Gemini planner.
    - `id` (string): Unique subtask ID.
    - `title` (string): Actionable subtask name.
    - `minutes` (number): Estimated time requirement.
    - `done` (boolean): Completion status.
- **`googleCalendarSynced`** (boolean): True if written to Google Calendar.
- **`telegramAlertDispatched`** (boolean): True if the recovery alert has been sent.

#### 2. `userSettings` Collection
Stores user preferences, integrations, and API configurations.
- **`telegramChatId`** (string): Linked Telegram chat ID for pushing alerts.
- **`telegramAlertsEnabled`** (boolean): User preference to receive critical alerts.
- **`telegramAlertSlots`** (array): Preferred times for daily digest delivery.
- **`geminiApiKey`** (string): Custom API key if the user opts out of the platform default.

### Security Rules
All Firestore access is tightly controlled via `firestore.rules`.
- Users can only read/write documents where `resource.data.userId == request.auth.uid`.
- Global reads/writes are disabled.

### Local Caching
The Node.js backend maintains a temporary volatile cache in `data/local_db.json` solely to support the Telegram Long Polling webhook without establishing redundant Firestore listeners on the server, optimizing cost and read-limits. Client-side states are synced to this cache via `/api/telegram/sync-state`.
